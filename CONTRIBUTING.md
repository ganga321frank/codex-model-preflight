# Contributing

Keep the installed skill small. Suggest a change using a sanitized task and the behavior that failed. Prefer fixing one distinction to adding a broad rule. Do not add background collection, automatic switching, or dependencies to the core advisory skill.

For a model-guide update, cite current official documentation, update the checked date, review affected public cases, and add a changelog entry. For trigger/continuation changes, review both positive and negative cases in `docs/cases.md`. If exact model labels are uncertain, retain capability-tier advice.

Before release, check YAML/frontmatter, local links, packaging, both installation paths, and the restart/continuation checklist. Record what actually ran in `docs/validation.md`; do not convert manual review into an accuracy claim. Public case labels are reference judgments, not ground truth for an optimal model.
